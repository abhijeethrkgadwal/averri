# SPEC-DECISIONS — Decision log for the V0 specs

Numbered, append-only. Each entry records a decision that deviates from the FINAL design document (`docs/research/00-FINAL-strategy-and-design.md`), resolves a conflict between review findings, or rejects a review finding, with the reason. Specs and types cite entries as `D-n`. Dates are the day the decision was applied to the specs.

Reviews referenced: **R1** = implementer-standpoint review of the IR/core types and specs (13 blocking, 17 important, 18 nits); **R2** = agent-consumer review of the MCP/diagnostics/declaration specs (4 blocking, 13 important, 10 nits).

---

**D-1 — Tier 3 is a bare async function; there is no `guard()` wrapper.** (2026-10-24; R1 blocking 13, R2 blocking 1; deviates from FINAL §4/§6 which spell tier 3 as `guard(fn)`.)
Both reviews reported that the worked example's `guard(async ({ input, actor }) => …)` fails `tsc` with `'input' is of type 'unknown'`, and proposed `GuardClause<I, R>` with inference from the contextual return type. That proposal was probed with `tsc` 5.9 and does **not** work: a call expression is not context-sensitive, so `guard(fn)` is checked in the first inference pass before the action's `I` has any candidate (the outer inference context maps `I` to the "no inference" wildcard), and `fn`'s parameter stays `unknown`. The only form TypeScript defers until `I` is known is a bare function expression, exactly as `run` already relies on. Therefore `requires`/`ensures` accept `AnalysableClause | GuardFn<z.output<I>, …>` and `policy.allow` accepts `AnalysableClause | PolicyGuardFn`. R2's option (a) ("let `action()` wrap bare functions, keep `guard()` for policies") was rejected because it creates two spellings for one concept (rule 1); with no input schema on policies `guard()` would add nothing there either. Construct count becomes "seven plus two builders". The IR tier name stays `guard`; the type-level distinction is `typeof clause === "function"`, and `e.and/or/not` reject functions by type. Verified in `packages/core/test/tier-types.test.ts`.

**D-2 — Static lowering only; no registry in core; compiler does not import core.** (R1 blocking 1, R1 nit 17.) The compiler lowers declarations and `averri.config.ts` from the statically analysable subset (SPEC-DECLARATIONS §4.1) and derives Zod field names/types from the TypeChecker type of `z.output<typeof schema>`. Evaluating user modules would connect Prisma and instantiate Inngest/Stripe clients inside the compiler. A1004 is the diagnostic for non-analysable options (A9001 stays the tsc backstop). The "module-local registry the compiler reads with tsx" is deleted.

**D-3 — `DbWhere` has one representation: canonical flat dotted keys, produced by the builder.** (R1 blocking 3.) The builder flattens nested source objects; runtime, IR and testgen see the same shape; `@averri/contracts` un-flattens into Prisma's nested `where` while substituting refs. Dotted keys may traverse only to-one relations; crossing a list relation or nesting `db.countWhere`/`sum`/`count` inside a `where` is A3009. Operator operands are restricted to `Ref | Lit | LenExpr` (`DbWhereOperand`, R1 nit 3).

**D-4 — Fail-closed predicates and 401 for anonymous actors.** (R1 blocking 2; R1 important 7.) Any `where` ref evaluating to `undefined` makes `db.exists`/`db.unique`/`db.none` false and `db.countWhere` 0, skips the Prisma call, and records `undefinedRefs`. `authorize` with `actor === null` on a non-public declaration returns `401 Unauthenticated` (`AUTHENTICATION_FAILURE`) before the policy runs. Three fixture tests are mandatory for `@averri/contracts`.

**D-5 — One declared-mode pipeline order; guards get the plain client; `transaction` passthrough.** (R1 blocking 4.) `validate → authorize (plain) → [tx] → load self (+includes) → requires (tier 1, 2, guards) → run → reload self → ensures (+invariants) → [commit] → emit`, written identically in SPEC-CONTRACTS §8, SPEC-DECLARATIONS §5.3 and core. `transaction?: boolean | { timeout?, maxWait? }` passes Prisma's interactive-transaction options through; `transaction: false` makes a postcondition failure report `committed: true`. The IR keeps `transaction: boolean` (the timeout is a runtime option, not a graph fact).

**D-6 — Observe mode wraps at the fetch boundary; `handler` is optional; test DB is the project's `DATABASE_URL`; no pglite.** (R1 blocking 5, R2 blocking 2.) Hono `app.fetch(req)`, Express `http.createServer(app)` on an ephemeral port; Averri's own route matcher; `handler:` feeds only `effect-scan`/line counts/A2101. Without `handler`, `effects.verified.complete = false` and A4002 is `info`. Before/after state is the subject row (`findFirst`) and the rows of entities with invariants (`findMany`, diffed by `@id`); predicates need no snapshot. FINAL §6's "pglite in-process by default" is impossible with Prisma without a driver adapter; the project supplies the test database via `config.test.databaseUrlEnv`.

**D-7 — A2103 redefined; no `public: true` fallback fix.** (R1 blocking 7, R2 blocking 4.) Warning: undeclared, non-public Exposure with no middleware in `config.authMiddleware`. Error: a bound declaration lacking both `policy` and `public` (only reachable when tsc is skipped); the sibling-policy fix applies to the error case only. The `public: true` fallback fix was removed because it is a hypothesis about authorization that the agent block tells agents to apply. `HealthCounters.exposuresWithoutPolicy` uses the warning definition.

**D-8 — Exposure ids carry a column; HEAD/OPTIONS are skipped; `all`/`on` expand.** (R1 blocking 9.) Id = `<router>:<file>:<line>:<col>` of the method identifier. Adding `HEAD`/`OPTIONS` to `HTTP_METHODS` was rejected: it would let declarations target them without any contract use case; they produce no Exposure. Mount-prefix composition, middleware attribution, normalisation and the confidence table are in SPEC-IR §4.1.

**D-9 — `verified` provenance lists every applicable verifier.** (R1 important 2, option (a).) `verifiers: VerifierId[]`; a node is verified iff all applicable verifiers passed. Named `verifiers` (plural) rather than the suggested `verifier: VerifierId[]`.

**D-10 — `dependsOn` is a directed propagation table, not an undirected ≤3-hop closure.** (R1 important 3.) Entities are hubs; the closure would mark most of the graph affected. Table in SPEC-IR §5; `X -dependsOn-> Y` means "X is affected when Y changes"; transitive ≤ 2 steps with `via`.

**D-11 — No runtime idempotency in V0.** (R1 blocking 11; deviates from FINAL §6 "in defineAction mode it is a primitive with a dedupe table migration".) A `averri_idempotency` table and its migration contradict "no application code in V0" and ARCHITECTURE §5. `idempotency` is a fact driving `pitfall.idempotency` ("single effect" = identical after-snapshots of `effects.verified.writes` tables between deliveries) and A5002. The dedupe primitive, replay semantics and TTL cleanup are Stage 2.

**D-12 — Emit failure after commit is trace-only.** (R1 important 7.) A 500 for committed work would make clients retry and double-write. `PHASE_FAILURE.emit.status` is `null`; the outcome is recorded in the trace with `committed: true` and fails the test under Vitest. Success status is 200 by default; adapters may override.

**D-13 — Generated Test nodes are derived from the graph; generated files are excluded from `contentHash`.** (R1 important 9.) Otherwise every build invalidates its own hash. `sourceHash` is compared with the `hash:` field of the `@generated` header for A6001; `contentHash` covers hand-written tests only.

**D-14 — Snapshots are keyed by `contentHash`; `last-green.json` pins its snapshot.** (R1 blocking 10.) `GraphMeta` cannot be diffed against a `Graph`; commits do not exist for dirty trees. `last-green.json = { meta, tests, at, snapshot }`; the referenced snapshot is excluded from the LRU-20 prune. `check` also writes `last-check.json` so `explain {diagId}` resolves (R2 important 3).

**D-15 — `entity.model` and `tenantKey` dropped.** (R1 important 17 and 4.) The entity name is the model name and the client accessor is `Uncapitalize(name)`; one fewer option to hallucinate (FINAL §11 risk 1). Tenant scoping in V0 is a policy predicate (FINAL §11.4); the V0 tenantKey check is removed. R2 important 7 asked to register A2106 as "Policy does not constrain tenant key" now; instead A2107 is **reserved** (comment in the registry) for the Stage 2 rule, because a registered code with no rule would be a dead entry agents can filter on but never see.

**D-16 — Diagnostic code allocations.** (R1 important 4, R2 blocking 3, R2 important 7 and 10, R1 nit 15; the two reviews proposed conflicting numbers.)
A1004 non-analysable option (also `$`-prefixed clause names) · A1005 keys out of canonical order (fmt check-only) · A2102 reserved · A2106 policy is an opaque guard (R1's meaning; R2's tenant meaning moved to reserved A2107) · A3007 ref-shaped literal on the rhs (R2's meaning; R1's "emitted/result outside ensures" is folded into A3003 as its text already allowed) · A3008 operator not applicable to operand type (R1; R2 wanted "unknown reference root" here) · A3009 where path crosses a list relation / nested db predicate · A3010 reference root looks misspelled (R2's "unknown root", renumbered) · A4005 integration called inside a Averri-owned transaction · A5001 demoted to warning without fix. Codes stay append-only; gaps are documented in the registry comment.

**D-17 — A5001 is a warning without a fix; webhook declarations carry `scheme` and `secretEnv`.** (R1 important 5.) FINAL §6 rejected static middleware-order checks; A5001 now inspects inline forms only and the runtime pitfall tests are the real check. A header name cannot tell the generator how to sign, hence `scheme: "stripe" | "hmac-sha256" | "custom"` and `secretEnv`; `pitfall.raw-body` is defined as a validly signed, non-canonically serialised body that must be accepted.

**D-18 — `result` is `unknown` inside `ensures` guards.** (Consequence of D-1; probed with `tsc`.) Typing it as `O` (the `run` return type) fixes `O` to `unknown` when an `ensures` guard precedes `run` in the object literal, because TypeScript assigns contextual parameter types with the fixing mapper; `NoInfer<O>` does not prevent fixing. Guards narrow `result` or use `e.result()`; typed results are the job of tier 1.

**D-19 — Actor fixtures are project-named with a mandatory `anonymous`; no `test.db: "pglite" | "testcontainers"`.** (R2 important 6, partially rejected.) R2 asked for `Record<"anonymous" | "member" | "otherTeamAdmin" | "admin", …>`; those are the reference app's roles, not Averri's. `actors: Record<string, ActorFixture>` with `anonymous: { actor: null }` required; fixtures carry `headers` so the app's own auth middleware produces the actor (R1 blocking 5c). The test database is an env var (D-6), not a mode switch.

**D-20 — Adapter default input gives path params precedence.** (R1 important 10, modified.) The review suggested `{ ...params, ...(GET ? query : body) }`; Averri uses `{ ...(GET ? query : body), ...params }` so a body cannot override a route-identified resource id (`teamId`). Default status 200; `Date` → ISO, `Decimal`/`BigInt` → string.

**D-21 — `find.limit` max is 30; `overview.agentBlock` renamed `quickstart`; `find` hit `path` typed.** (R2 nits 3, 4, 10.) Hits are ~80 chars; above ~35 the budget always truncates.

**D-22 — `averri fmt` is check-only in V0 (A1005).** (R1 nit 11.) Rewriting object keys in TypeScript source (comments, trailing commas) is over-scoped; reordering is Stage 2. Clause order inside `requires`/`ensures` is never checked (R2 nit 9).

**D-23 — MCP inputs are root `z.object`s; `impact` accepts `{}` for "uncommitted edits".** (R1 blocking 12, R2 important 5.) `z.toJSONSchema` of a root union yields `anyOf`, which MCP clients reject.

**D-24 — Id-derived file names use `encodeURIComponent(id)`.** (R1 important 15.) Ids contain `:` (illegal on Windows) and `/` (creates directories). Chosen over `:`→`__`, `/`→`~` because it is reversible without reserving characters.

**D-25 — Packaging requirement recorded, manifests unchanged.** (R1 important 16.) `tsc -b` to `dist/`, `exports` to `.js`/`.d.ts`, and the devDependencies `averri init` must add are specified in ARCHITECTURE §7; editing package manifests is out of this task's scope and belongs to the first implementation PR per package.

**D-26 — No text-search mode on `find`.** (R2 important 13, alternative chosen.) A ripgrep passthrough would be a second search tool with its own budget; agents already have grep. The agent block and SPEC-MCP §6.2 say explicitly what `find` covers and when to grep.

**D-27 — `Path` keeps root autocomplete: `RefPath | (string & {})`.** (R1 important 1 asked to delete the dead template-literal members or type `e` per action; R2 important 10 asked for `RefPath | (string & {})`.) The R2 form keeps editor autocomplete for the five roots without collapsing to `string`; per-action typing of `e` would change the API shape. The deviation from FINAL §4 ("tsc checks field names") is stated in SPEC-CONTRACTS §2; the compiler checks fields (A3002/A3003/A3010).

**D-28 — Ref-shaped string literals on the rhs are a type error (`NoRefString`) and A3007.** (R2 blocking 3.) Implemented as `rhs: R & NoRefString<R>` so `R` still infers from the argument; probed with `tsc`.

**D-29 — `policy`/`public` are separate overloads so `actor` nullability is honest.** (Consequence of D-4.) `actor: Actor` under a policy and `Actor | null` when public, in `run`, guards and adapters. `AnyActionDecl`/`AnyQueryDecl` use `any` for the contravariant slots, as tRPC-style libraries do; `run` is declared with method syntax so specific declarations stay assignable to the erased forms.

**D-30 — README example updated; ROADMAP and JOURNEY left as written.** README's twenty-line example used `model:` and `guard(...)`, which no longer type-check, so it was brought in line (reads edges wording, 412 wording). JOURNEY describes the FINAL doc historically and is accurate; ROADMAP line 19 still lists `guard` among the core exports and should be updated in a follow-up (out of this task's file scope).

**D-31 — `history` is bounded; `suggest` ranks by handler write count.** (R1 important 13.) ≤ 20 commits from `git log -- <file>`, snapshots reused, stop at 10 ops or 10 s, `truncated` reported. Undeclared Exposures have too few edges to rank by "edge traffic".

**D-32 — Schema drift checks are mutual-assignability aliases, not `ZodType<T>` annotations on node schemas.** (R1 nit 5, modified.) Annotating each node schema as `z.ZodType<EntityNode>` breaks `z.discriminatedUnion`, which needs `ZodObject`s. `_SchemaDriftChecks` asserts `z.output<typeof XSchema>` and `X` are mutually assignable for all twelve node kinds; `NodeSchema` is then annotated `z.ZodType<Node>` without a cast.

**D-33 — Rejected: single-verifier semantics kept at node level only (R1 important 2 option (b)).** Option (a) was chosen (D-9) because tools render node provenance, and "verified by route-match only" would be misread as fully verified.

**D-34 — Rejected: `check` scope "affected" stays the default.** (R2 nit 5 asked for clarification, not a change.) Defined fallbacks: dirty tree → HEAD..working tree; clean tree → last-green..HEAD; no last green → `all`; an empty affected set is never silently green.

**D-35 — `@averri/core` runtime marker, call-time validation scope, and key orders for non-action constructs.** (2026-10-24; first implementation of `@averri/core`.) (a) Constructors attach a NON-ENUMERABLE `__averri` property (`AVERRI_MARKER`, read with `averriMeta(decl)`) carrying the IR node id and the lowered contract records (`{ id, phase, clause, tier, expr | null, guard | null, opaque }`), plus the flattened `subject.where`, resolved `transaction` and the resolved integration/workflow defaults, so `@averri/contracts` executes declarations without re-deriving anything. The enumerable surface stays exactly `{ kind, id | name, mode?, options }` (events add `id`), so `JSON.stringify`/deep equality see pure data and the compiler's static lowering (D-2) is unaffected. (b) Core validates at call time only what is structurally decidable without schema facts: option-name sets, literal unions, `policy` XOR `public: true`, `run` XOR `handler`, `route` in observe mode, `transaction` only in declared mode, clause-name grammar (`$` reserved, camelCase), phase/root rules (SPEC-CONTRACTS §2 table, `e.emitted` in `ensures` only), `self`/`old` refs requiring `subject` (refs inside `exists`/`count` element filters excepted), path depth ≤ 3 and `where` depth ≤ 3. Field existence, model names and type applicability remain compiler diagnostics (A1003, A3002, A3008, A3009). A doubled prefix (`e.input("input.x")`) is deliberately NOT normalised (A3002 fix territory). `subject.where` may reference `input`/`actor` only. (c) `averri fmt` key orders for `entity`, `policy`, `event`, `workflow`, `integration` are exported as `CANONICAL_KEY_ORDERS` (`intent` first, options in spec order, `owner`, `tags` last); only the `action`/`query` order is normative in SPEC-DECLARATIONS §4, the others are core's convention. (d) `integration.effects`/`nonTransactional` and `workflow.engine` defaults are resolved in the marker, never written back into `options`, so the runtime object and the statically lowered IR agree on what the user wrote.

**D-35 — `@averri/ir` helper semantics the specs leave open.** (2026-10-24; implementation of SPEC-IR §5, §7, §11.) (a) `diffGraphs` reports `change` ops for payload differences except, by default, the top-level properties `src`, `provenance`, `summary` (they move with every edit, so `history` would be all noise) and `lastResult` (written by `check`, not `build`); `ignore: []` reports everything. A Contract whose AST/tier changed yields exactly one op attributed to its owner (`node` = owner, `target` = contract id): `weaken-contract`/`strengthen-contract` per SPEC-CONTRACTS §7, or `change` when undecided (this is the `op: "change"` entry of `contractsWeakened`); tier 1/2 → guard is weakening, guard → tier 1/2 is undecided. Renames detected on an Action/Query propagate to its Contracts (`Contract:<new>.<phase>.<clause>`) and generated Tests, so a rename never shows as `remove-contract` + `add-contract`. (b) `dependsOn` edges need a `Provenance`; a computed edge carries the lowest-ranked provenance among the facts it was derived from (the underlying edge, or the Contract node whose refs/`where` name a Field; two-step edges take the lower step). Field resolution for the "Contracts whose `where`/refs name the Field" row: `self.*`/`old.*` through the owner's `subject.entity` (or the Entity itself for invariants), `result.*` through `output.entity`, `db.*` keys through the model's `clientName` and to-one relation Fields; `input.*`/`actor.*` never name a Field. (c) `validateGraph` is `GraphSchema.parse` plus the §6 invariants (`nodes[id].id === id`, `counts` per kind and in sum) and, by default (`strict: true`), the §2.1 id grammar and edge-endpoint existence; a cache failing any of these is rebuilt. (d) `HealthCounters.staleGeneratedTests` needs the generated files, which `ir` cannot read; `computeHealth` takes it as a number or a predicate over generated Test nodes from the compiler.

**D-36 — `@averri/extract` semantics the specs leave open.** (2026-10-24; first implementation of `@averri/extract`.) (a) `app.all(path)` expands to five Exposures (SPEC-IR §4.1) but the id grammar has one position per registration; the expansion uses the method identifier's line and column for GET and column + 1..4 for POST/PUT/PATCH/DELETE, in `HTTP_METHODS` order, so ids stay unique and parse with `parseExposureId`; `src` and evidence point at the real registration. `app.on([...], path)` uses each method literal's own position; `on` with a non-literal method list produces no Exposure and a `route-dynamic-path` warning. (b) Hono `basePath("/api")` is a mount prefix for the confidence table: a route registered directly on `new Hono().basePath("/api")` is "composed through a static mount prefix" (0.95), not 0.98. A dynamic path or dynamic prefix is rendered with `${expr}` placeholders (`/api/${version}/info`) so it cannot be mistaken for a literal; `normalizeRoutePath` keeps those placeholders. (c) `use()` middleware applies to registrations that follow it in source order (chain order inside one statement, statement order inside one file, then path order across files; a mounted router's registrations take the mount's position). A `use()` with a non-literal pattern attributes nothing. Express `app.use(prefix, mw, router)` attributes `mw` to the mounted routes. (d) The mount tree's roots are unmounted instances in `entryPoints`; without configuration every unmounted instance is a root and `entry-points-detected` is warned. Receivers that cannot be traced to a creation expression (`function register(app: Hono)`) are "unresolved" instances: their registrations get 0.5 / `dynamic: true` with `route-receiver-unresolved`, like never-mounted routers. An instance mounted twice keeps its first path (`router-mounted-twice`). Express `app.route(path).get(h).post(h)` builders are supported; `head`/`options` are skipped (D-8). (e) There is no edge kind for Prisma relations, so relations are Field nodes with `type.kind: "relation"` plus `ExtractResult.prisma.relations` (`fields`/`references`/`name`) for the compiler's A3009 checks; views are skipped with `prisma-view-skipped`, a model whose field type is unknown yields `{ kind: "unsupported", raw }` at 0.9 with `prisma-unknown-type`. Positions are computed from the schema text (the parser runs without location tracking). (f) Hand-written Test nodes are one per `it`/`test` call (`Test:<file>:<line>`, title = `describe > ... > title`); `covers` comes from `// @averri covers <ids>` comments (before the first call: whole file; above a `describe`: its tests; above an `it`: that test) and from node-id string literals inside the test. The extractor records `covers` only; `verifiedBy` edges are created by the compiler's `test-link` verifier, because the covered node may not exist. (g) Zod schemas have no node kind; `ExtractResult.zodSchemas` carries `{ ref, exported, fields, complete, method }` for variable declarations and one level of object-literal members (`InviteMember.input`). The AST is tried first (`object`/`extend`/`merge`/`pick`/`omit`), the TypeChecker's `shape` property second; a shape neither can decide is `complete: false` with `zod-shape-unresolved`. `Exposure.bodySchema` is the first Zod reference among validator-middleware arguments, else the first `schema.parse(...)` receiver in the handler body. (h) Module `role` precedence is config > test > declaration (imports `@averri/core` and calls a constructor) > route (creates a router or registers routes) > handler (declares a symbol a registration references) > other; Module nodes use extractor `ts-handler` at confidence 1. `contentHash` = sha256 over the path-sorted `"<path>\0<sha256>"` lines of sources, hand-written tests, the Prisma schema, `package.json` and `averri.config.*`, generated tests excluded (D-13). (i) `@mrleebo/prisma-ast` is imported through its ESM build path because its CJS `main` cannot load the ESM-only `chevrotain` under Node/tsx.

**D-36 — `@averri/contracts` runtime semantics the specs leave open.** (2026-10-24; first implementation of `@averri/contracts`.) (a) *Runtime binding.* `handle(decl)` in core's `DeclaredRuntime` has no slot for the Prisma client, so the package exports `handle(decl, runtime)`, `toHono(decl, adapterOptions & runtime)`, `toExpress(...)` and `invoke(decl, { input, actor, ...runtime })`, plus `createRuntime(runtime)` which returns the core-typed `DeclaredRuntime`. `runtime = { prisma, config?, declarations?, recorder?, production?, random?, status? }`; `declarations` resolves entity NAMES (`subject.entity: "Invitation"`, `output: "Invitation"`) to invariants, `recorder: null` disables trace files. Likewise `observe(app, { declarations, config, prisma?, recorder? })` extends core's `ObserveOptions` with the client (core's shape is unchanged). (b) *Tier-2 evaluation order.* `db.*` nodes of a clause are evaluated up front (one `count` each, skipped under the undefined-ref rule), then the expression is evaluated synchronously; `e.and` therefore does not save a predicate's query by short-circuiting. This keeps one evaluator for both tiers and lets `evaluateExpr` stay synchronous for the test-time auth matrix. A Prisma error inside a predicate fails the clause (fail closed) and is reported in the record message, never thrown. (c) *`undefinedRefs`* lists every ref resolving to `undefined` except the argument of `isNull` (where `undefined` is the meaningful "absent" case). `evaluated` holds, for a failing `and`, only the failing conjunct's leaves; for a passing `and` all leaves; for `or` every leaf evaluated; element filters of `exists`/`count` record the aggregate node, not per-element leaves. `lt/lte/gt/gte` over non-numeric, non-date operands are `false` at runtime (A3008 is the static check); `BigInt` is compared through `Number`. (d) *Subject include.* The runtime `include`s relations named by `exists`/`count`/`sum` paths rooted at `self`/`old`; `len` is ambiguous (string or list) and is not included. Undefined refs in `subject.where` load no row (`self` null), consistent with predicates. (e) *Trace `committed`.* `true` for `emit` failures and, without a transaction, for `run` and `ensures` failures (writes may have persisted); the body `committed: true` appears only on `PostconditionFailed` with `transaction: false`, as SPEC-DECLARATIONS §5.3 states. Emitting with `config.emitter === null` is an `emit` trace failure (`ok: false`, response unchanged). Unexpected errors (a `$transaction` failure, a misconfigured client inside the transaction) are `500 HandlerError` and traced; missing `$transaction` on a client with `transaction !== false`, or an observe-mode declaration passed to `invoke`, throw `AverriRuntimeError` before any trace. (f) *Observe mode.* Only observe-mode declarations are matched (declared-mode ones served through the adapters record their own traces). Two `authorize` records are written per request: Averri's evaluation (`observed: false`) and the app's status-derived decision (`observed: true`, `ok` = the two agree on deny/allow); `requires`/`ensures` are evaluated only when the declared schema accepts the input (a `validate` failure with a 2xx response is itself the trace outcome); invariant entities are re-read with `findMany()` and diffed by `id` (fallback: canonical JSON), one record per violated invariant; the emitter spy accepts `send("name", payload)`, `send({ name, data })` and arrays of events and strips `eventNamePrefix`. Without `prisma`, predicates fail closed and the subject is `null`. (g) *Serialisation.* `serializeResult` maps `Date` → ISO, `BigInt`/Decimal-like (`toNumber()`) → string, drops `undefined` properties, and sends `null` for an `undefined` result. Trace files use the UTC date in the name; retention pruning runs once per process on the first write.

**D-37 — `@averri/testgen` derivation choices the specs leave open.** (2026-10-24; first implementation of SPEC-CONTRACTS §9.) (a) Generated tests drive the application through a small test-harness surface exported by `@averri/contracts` (`createTestHarness({ config, app, modules })` returning `invoke`, `rawRequest`, `policyDecision`, `parseInput`, `actor`, `prisma`, `snapshot`, `emitted`, `consumerRegistered`, `invariantViolations`, `close`; normative TypeScript in `packages/testgen/src/harness-api.ts`). Declarations are resolved at test time by id from the module namespaces the generated file imports (the declaration's `declaredAt.file`), never by export name, because the IR does not record the exported const. The app is the `default` or `app` export of the configured entry point. (b) `sourceHash` is `stableHash` of the owner's derivation inputs computed from the graph (owner node, its Contracts, Policy and allow Contract, the Entities/Fields its predicates and subject/output/writes name, consuming Workflows, the webhook Exposure's method/path), excluding `src`, `provenance`, `summary`, `ratios` and `lastResult`; moving a declaration does not regenerate its tests. The compiler derives Test nodes with `deriveTestNodes(graph, options)` and gets the same hash without rendering. (c) Auth matrix: the expected decision is `h.policyDecision` at test time as specified; for predicate policies the generated test first seeds the policy's satisfying rows for the fixture's actor (and, in a second row per fixture, the falsifying rows) so both directions of the app-vs-policy comparison are exercised; the "allow" column asserts non-4xx (declared) / 2xx (observe) only when every precondition is derivable and the action has no guard, otherwise it asserts "not 401/403". (d) Fixture synthesis uses the `<relation>Id` / `<relation>_id` / `<relation>ID` scalar convention for foreign keys (the IR has no `@relation(fields:)`), creates rows in Prisma's unchecked form (FK scalars, parents first), and draws nonce-suffixed values for `@unique` columns instead of "drawing until unique"; a `db.unique` predicate is falsified like `db.exists` (first `where` key altered). (e) Single-shot tests draw the input through `h.parseInput` (up to 50 samples) because the static arbitrary is derived from field names, contract literals and schema facts, not from the Zod schema, which the compiler never evaluates (D-2). (f) `verifiedBy` edges are emitted only from node kinds the edge table permits; an invariant suite therefore lists its Entity in `covers` but its edges come from the invariant Contracts.

**D-38 — `@averri/compiler` semantics the specs leave open.** (2026-10-25; first implementation of `@averri/compiler`.) (a) *Analysable subset.* Besides the forms in SPEC-DECLARATIONS §4.1 the lowering accepts numeric arithmetic over literals (`30 * 24 * 60 * 60`, constant-folded, nothing executed) and, on the right of a comparison or as a `where`/`in` value, an identifier whose TypeChecker type is a literal (`const PENDING = "pending"`); a `const` bound to an `e.*`/`db.*` chain in a module that imports `@averri/core` is lowered like the chain itself. Fidelity is tested by comparing every lowered contract AST of the seed app with the runtime builders' output (canonical JSON). (b) *Where diagnostics are raised.* Facts that make a clause unrepresentable are reported while lowering and the clause/option is omitted: A1001, A1003, A1004, A3004, A3009 for `sum`/`count`/`db.countWhere` nested in a `where`, and A4001 for `e.emitted(X)` with an undeclared X; every other code is a rule under `packages/compiler/src/rules/<code>.ts`. A1003 for an unknown `entity("X")` uses `Entity:X` as `node` although no such node exists. (c) *A1005* checks only the normative action/query key order; the other constructs follow core's convention (D-35c) and are not reported. (d) *effect-scan* passes only when the scan is complete (`complete: true`) and the declared effects equal V (actions) or no write was found (queries); an incomplete scan never verifies. Raw `$executeRaw`/`$queryRaw` count towards `db:write`/`db:read` in V. Workflow runners are scanned too and contribute verified `writes`/`calls` edges. An observe-mode Action without `handler` gets ONE `A4002` at `info` ("effects unverified") so the gap is visible (SPEC-DECLARATIONS §6); with a handler, rule 6 of SPEC-IR §3.1 applies unchanged. (e) *emit-scan* passes when the body was fully scanned, every `emitted` clause's event is emitted, `event:emit` is declared iff something is emitted, and no `emit()` target is undeclared. *zod-match* passes when the input field set is known and no A3002/A3006 concerns the declaration's input. *consumer-scan* passes when a consuming workflow's runner contains the string literal `eventNamePrefix + name`. *test-link* creates `verifiedBy` edges (provenance `verified`, verifier `test-link`) for covered nodes of permitted kinds and trims `Test.covers` to them; hand-written Test nodes stay `extracted`. (f) *A3002/A3006/A3008 typing.* `actor.*` refs and refs inside `exists`/`count` element filters are not field-checked (no static Actor facts; element scope); A3006 compares an `input.<field>` with the Prisma field it is compared to or used as a `where` value for (comparisons, `db.*` where clauses, `subject.where`); writes in `run` and nullability are not compared; DateTime accepts a Zod string (ISO). (g) *Fix patches* are standard unified diffs (Myers line diff, one hunk per region, 3 context lines), dry-run applied in memory before attachment; patches over 4 000 chars are dropped. The A2103 sibling-policy fix inserts `policy: <Sibling>` after `output`, else `input`, else `route`. (h) *Generated tests on build.* `build()` writes `tests/averri/*.gen.test.ts` only with `writeTests: true` (the CLI's `averri build` and `check` pass it; `loadOrBuild` for MCP queries does not), rewriting a file only when its header hash differs and deleting only files with an Averri `@generated` header whose owner vanished. (i) *Revisions.* `impact {diff}` builds the "before" tree from a temporary copy of the input files next to the project root with the diff reverse-applied (so relative tsconfig `extends` and `node_modules` resolution are unchanged); `{base}`/`check` against a ref use a temporary `git worktree` with a `node_modules` junction; both reuse `.averri/snapshots/<contentHash>.json`. (j) *check* writes `Test.lastResult` into the cached graph.json (build never does), selects tests from `impact` of the chosen base plus tests in changed files, and runs all generated tests (saying so in `coverage.message`) when the affected set is empty; `-t` patterns in `rerun` are regex-escaped. (k) *explain* maps a trace's actor id to a fixture name through the static `actor.id` literals of `config.actors`. (l) *find* returns `more` only for hits dropped by the token budget, not for hits beyond `limit`.

**D-39 — `@averri/mcp` semantics the specs leave open.** (2026-10-25; first implementation of SPEC-MCP.) (a) Low-level `Server` with `z.toJSONSchema(schema, { io: "input" })` (so defaults are optional in the schema), not `McpServer.registerTool`. (b) Tool results are one JSON text block (`serialize(result)`), `isError` when `ok: false`; unknown tool name is `bad-input`. (c) Every tool, including `read_source`, loads the graph first, so a failed rebuild (e.g. lock timeout) is `build-failed` for all of them. (d) HTTP is stateless (new server per request), `/mcp` POST only, bound to 127.0.0.1. (e) `suggest` ranks undeclared Exposures by Prisma write calls in the handler range, then deeper path first, then id; drafts go to `<handler module>.averri.ts` (new file or appended), several proposals for one file apply in order; with no shared sibling policy it emits a `// policy: TODO` comment (fails typecheck on purpose) rather than guessing `public: true`; `requires` only from `findFirst/findUnique/count` guards and `ref OP literal` comparisons that precede a 4xx throw/return. (f) Docs cards are condensed strings in `src/docs.ts`, size-tested (core <= 1500, others <= 300 tokens).

**D-39 — `@averri/cli` semantics the specs leave open.** (2026-10-25.) (a) *No tool logic in the CLI.* Every tool command calls `callTool` from `@averri/mcp` and `--json` prints `serialize(result)`, so CLI and MCP output are byte-identical by construction; `suggest`, the agent block text and the MCP registration snippet come from `@averri/mcp` too. (b) *Exit codes.* 0 ok; 1 for error-severity diagnostics (`build`, `report` for diagnostics introduced vs the base, `fmt --check` when files would change), a `check` that is not green, and tool errors other than `bad-input` (`not-found`, `ambiguous`, `low-confidence`, `build-failed`); 2 for commander usage errors and tool `bad-input`. (c) *`fmt` writes by default.* The task for this package asks for canonical key order via ts-morph with a `--check` mode, which supersedes D-22's "check-only in V0" for the CLI; `--check` never writes. All seven constructs are reordered with the compiler's `CANONICAL_KEY_ORDERS` (only action/query are normative; the rest follow core's convention, D-35c). Each property keeps its own text and leading comments; unknown keys stay behind the key that preceded them; objects with spreads, computed keys or duplicate keys are skipped and reported. (d) *`init`* writes `.cursor/rules/averri.mdc` (frontmatter `alwaysApply: true` + the block) rather than a file named `.cursor/rules`, because Cursor rules live in that directory; it edits package.json only by adding missing `@averri/core` (dependency) and `vitest`, `fast-check`, `@averri/contracts` (devDependencies) and never runs an install; MCP registration is printed, not written. (f) *`report`* uses the full `impactOfGraphs` result minus the raw graph diff, adds `summary`, diagnostics introduced/resolved by (code, node, title), and writes `.averri/reports/<sha>.json`. (g) *`testgen --only`* writes only the selected files and deletes nothing; plain `testgen` uses the compiler's writer (which deletes orphaned generated files). (h) `@averri/testgen` is a direct dependency of the CLI (ARCHITECTURE lists compiler and mcp only) because `testgen` needs `generateTests` and the compiler does not re-export it.

**D-40 — Integration: the generated-test harness, fixture seeding against a real app, observe-mode emits, and check's tsc.** (2026-10-25; integration of all packages against `examples/seed-app`.) (a) *`createTestHarness`* is implemented in `@averri/contracts` (`src/harness.ts`) with the surface of `packages/testgen/src/harness-api.ts`, plus two members the generated code now needs: `conformInput(owner, raw)` and `PrismaModelLike.updateMany`. Declarations are resolved by `averriMeta(decl).id` over every export (and array export) of `modules`; the app is the entry module's `default`/`app` (a Hono-style app, an Express listener, or `{ app }`); the Prisma client is `init.prisma`, else the entry module's `prisma`/`db` export, else `new PrismaClient()` from the project's `@prisma/client`. Observe-mode invokes go through `observe()`; requests to a declared integration webhook route are signed with the declared scheme (`stripe`, `hmac-sha256`) when the secret env var is set, over the exact bytes sent. `emitted()` comes from an outer spy on `config.emitter.spy`. `consumerRegistered` requires the workflow's `on` to be the event, the runner's own event name (`runner.event`, `runner.events`, Inngest `opts.triggers`) to match when it has one, and the emitter's `subscriberCount`/`listenerCount` to be positive when it has one. (b) *Schema-guided inputs.* When no sample of testgen's static arbitrary passes the declared Zod schema, `conformInput` keeps the fields the schema accepts, drops rejected optional fields and re-samples required ones from the schema (Zod 4 `_zod.def` introspection; transforms sampled on their input side; regex formats through fast-check's `stringMatching`); refinements it cannot satisfy yield null and the generated test reports it. Property tests use `conformInput` with `fc.pre`. (c) *Observe traces* carry an `emit` phase record (after `run`) when the spy saw an emission, so `emittedCount(trace)` works in observe mode. A 404 counts as the app's denial when the declared policy denies (`observed: true`, decision `deny`), and the generated observe-mode auth matrix accepts 401/403/404 for denied actors; for allowed actors a 403 is accepted when the trace shows a failed `requires` (a business rejection the app reports as 403). (d) *Fixture seeding.* Field node `name` is the qualifier (`Membership.role`, SPEC-IR), so testgen derives the bare column from the id. A top-level `or` policy is seeded per disjunct: `satisfy` seeds disjuncts in order until the declared policy allows the fixture, skipping a disjunct whose actor-only comparisons (`e.eq("actor.type", "user")`) fail for the fixture; `falsify` falsifies every disjunct. Unpinned required columns, falsified literals and subject-violation draws stay inside the column's closed domain (single-comparison entity invariants such as `e.in(col, [...])`, else the Prisma enum); `db.exists` is falsified on a literal-valued column of the row when it has one (`deletedAt: null`), else on the first key. **D-41 — Review round 3 fixes: where the code now deviates from, or tightens, the specs.** (2026-10-25.) (a) *Fail closed under `not` and on Prisma errors* (SPEC-CONTRACTS §4, §5). `db.countWhere` with an undefined ref used to be `0`; it now poisons the clause instead (the whole `requires`/`ensures`/`allow` clause is false), because `0` let `e.lte(db.countWhere(...), 2)` pass for an actor without an id and `e.not(db.exists(...))` turned the fail-closed `false` into `true`. The same poison applies when a Prisma `count` throws (any `errors` fails the clause in `evaluateClause` and `evaluateContract`) and when a ref resolves to `undefined` underneath an `e.not` (a negated missing value is not evidence). `isNull` is exempt (a missing field is null by definition). The `evaluated` record keeps the values that were seen; `undefinedRefs` still lists the refs. (b) *Observe-mode `old`* is `deepCopy(self)` like declared mode, not `toJsonValue(self)`, so `Date`/`Decimal`/`BigInt` columns compare numerically across `old`/`self`. (c) *Handler modules.* Every Module that is the target of an `implementedBy` edge is promoted to `role: "handler"` in `build()` before `computeDependsOn` (the extractor only sees handlers passed straight to a route registration), so the SPEC-IR §5 propagation rule fires for service modules named by a declaration's `handler:`. (d) *Budgets measure the response* (SPEC-MCP §1, §6.5, §9): `responseTokens(data, more)` counts the envelope fields, `more` and `data`; every tool (`overview`, `find`, `inspect`, `impact`, `check`, `explain`, mcp `bound`) uses it. `more` is capped at 10 entries (`capMore`: nine handles and `+N more`), so spec §6.5's "rest in `more`" holds for the first handles only; the rest are found with `find kind=Test` or a narrower `scope`. `check` drop order: coverage tests beyond 20, then repeated diagnostics of one (code, title) collapse into the first (the others' nodes go to `more`, the kept message says `+N more`), then coverage tests, then diagnostics from the end (warnings first), then failures; `more` lists failures and diagnostic nodes before test ids. (e) *Hand-written tests in `check --scope affected`* are selected when their import closure (ts-morph module resolution, `import`/`export from`/`import()`/`require()`) reaches a changed file, where changed files are the git-changed paths plus every Module the graph diff reports changed; `// @averri covers` headers stay an additional selector. `coverage.message` says how many hand-written tests in how many files were not selected. (f) *Undeclared Exposures get extracted `reads`/`writes` edges* (SPEC-IR §3) from effect-scan of their resolvable handler (confidence 0.8, 0.6 for an incomplete scan; below 0.9, so impact consumers see a `verify` hint). `impact` also lists the Contracts whose `of` is a changed Entity. Not done: a route whose handler cannot be resolved statically still has no edges and no `incomplete` marker. (g) *`apiBreaking`* compares the multiset of `METHOD path` over Exposures (an Exposure id embeds `line:col`, so an inserted import shifts every registration and the diff pairs unrelated ones); a removed or edited method/path is breaking, a moved registration is not. An Action/Query `rename` is breaking only if its route differs, and `route.exposure`/`route.verified` changes are ignored. Narrowed input types are not detected (the IR stores field names, not Zod types). (h) *`requestFor` and `mergeInput` agree* (D-20): `GET`/`HEAD` carry non-path input in the query, every other method, `DELETE` included, in a JSON body; a `DELETE` with only path params stays bodyless. (i) *`consumerRegistered`* with an emitter that exposes no `subscriberCount`/`listenerCount` passes only when the runner object names the event (`event`, `events`, `triggers[].event`); a workflow's own `on` is not evidence, and an unrecognisable runner is `false` (fails closed). Chosen over a tri-state because `@averri/testgen`'s `harness-api.ts` types the method as `Promise<boolean>`. (j) *Snapshots are version-gated:* `readSnapshotByHash(root, hash, averriVersion)` rejects a snapshot written by another Averri build, `buildDir` in `revisions.ts` passes the current version, and `writeSnapshot` replaces a same-hash file whose `averriVersion` differs; the pinned last-green snapshot is read by name and is not gated.
